# Botanical Profiles and References

Botanical profiles will provide reusable data describing flower, leaf, and plant forms. They should support both evidence-based traits and clearly labelled artistic controls.

## Profile principles

1. Record common and scientific names where known.
2. Cite reliable botanical references for factual claims.
3. Separate observed botanical traits from procedural approximations.
4. Document uncertainty and natural variation.
5. Avoid implying that one parameter set represents every cultivar or growing condition.
6. Keep profile data versioned so changes can be tracked.

## Suggested profile information

- Common name
- Scientific name and taxonomic authority, where verified
- Organ type (petal, leaf, stem, flower, plant)
- Shape and proportion notes
- Arrangement and attachment notes
- Growth habit and branching notes
- Reference links and access dates
- Confidence or evidence notes
- Procedural parameter mapping
- Known limitations and variation

## Evidence and attribution

Prefer botanical gardens, university resources, peer-reviewed publications, floras, and reputable taxonomic databases. Record source details close to the claims they support.

Photographs, scans, diagrams, and datasets may have separate copyright or database rights. A source being publicly viewable does not automatically permit redistribution.

## Procedural approximation

A generated mesh is an artistic and technical approximation. A profile should state which features are represented, which are simplified, and which are not yet modelled.

## Example profile outline

```yaml
profile_id: example-flower
common_name: Example flower
scientific_name: ""
organs:
  petal:
    shape_profile: ""
    symmetry: ""
    arrangement: ""
references: []
notes:
  verified_traits: []
  procedural_approximations: []
  limitations: []
```

This is an illustrative outline, not a finalized schema.
